## Narrowness and limits
Choice content is NOT parsed as a substitute forecast. JSON whitespace outside strings is removed and the result must exactly match serialization of the validated bounded plain-data response snapshot. This conservatively rejects property reordering, alternate numeric/escape encodings and duplicate keys, even when some alternatives are semantically equivalent. The adapter avoids ambiguous duplicate-key parsing; public tests contain synthetic examples only. Object-only strict semantic validation then still enforces forecast-vs-abstain/null, finite range, source membership/uniqueness/count, rationale limits, expected question, usage and token cap.

Snapshots reject ordinary accessors, symbols, custom prototypes/iterators, sparse arrays and unexpected fields without deliberately calling getters or toJSON. Proxy traps cannot be universally detected or guaranteed side-effect-free in JavaScript; inputs must come from trusted transport decoding, not arbitrary caller code. Throwing traps are rejected. No endpoint accepts supplied forecast or provider objects.

Numeric binding statuses are observed values, possibly stale, not proof of failing-request HTTP status. A rejected promise always stops regardless of observed 200.

Schema validity does not prove forecast accuracy or evidence adequacy. This candidate uses synthetic fixtures only and has not processed live competition questions.
