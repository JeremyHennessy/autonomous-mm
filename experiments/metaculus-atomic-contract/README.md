# Synthetic atomic submission contract, OFFLINE ONLY

Run `node --test test.mjs`. Pure descriptor, acknowledgement and reconciliation helpers; no HTTP client, credential, storage, model, live runner import or publication. All context fixtures are fictional. The mandatory synthetic flag prevents confusing this module with an enabled live adapter.

`makeDescriptor(context, forecast, now)` produces a deeply frozen single-forecast/single-comment request body plus deterministic UTF-8 JSON and SHA-256 digest. The digest binds exact comment content, probability, IDs, author, frozen configuration/round and eligibility context. It is integrity linkage, NOT a signature or proof of eligibility. Context booleans are normalized caller assertions; no service verification is performed. Synthetic flags in tests are not actual registration/primary-bot approvals.

The body uses question ID in forecasts and post ID in comments, omits acting_user, sends private reasoning with included_forecast:true, and adds no marker. IDs belong to separate namespaces; equal numeric IDs are not forbidden but one is never inferred from the other. Verified single-question binary mapping postQuestionId===questionId is mandatory because the backend selects the latest own forecast from on_post.question when attaching it. Groups/conditionals unsupported. Only finite numeric probabilities 0.001–0.999 inclusive are allowed. Abstention, strings, endpoints 0/1 and out-of-range values are rejected, never clamped. Reasoning is exact, nonblank and locally capped at 4,000 UTF-8 bytes.

`acknowledge` accepts only HTTP 201 / empty-object evidence with request digest, matching author, verified request correlation and nonrollback receipt time. These extra correlation fields are a normalized trusted-transport contract, NOT fields returned by Metaculus. Output acknowledged does not invent forecast/comment IDs or idempotency. Invalid/absent/error evidence remains unknown.

`reconcile` requires fresh complete evidence of one exact own forecast and private comment, included forecast linkage, and authoritative correlation of those records to this request digest. Matching text, values, author and close timestamps alone are insufficient. The documented API does not establish this request-to-pair proof; a future trustworthy method must be reviewed, otherwise uncertain submissions stay unknown permanently. Synthetic positive tests prove predicate behavior, not availability of authoritative API evidence. Read-only reconciliation may happen after expiry without authorizing new writes. Every outcome has retryAllowed:false, including errors and unknown; no retry decision or blind replay is implemented.

Restored serialized descriptors are reconstructed and checked; malformed descriptors fail closed. Ordinary accessor/nonenumerable/extra fields are rejected; arbitrary hostile JS Proxy traps are not a guaranteed side-effect-free boundary. Use trusted normalized JSON, never caller-executable objects.

## Remaining runtime gates
This is a pure module, not a durable writer or an enabled submission adapter. No live publication is authorized. Before any eventual adapter: explicit registration/primary-bot/eligibility and API access verification; frozen protocol/round; authentic account/author and question-post mapping; fresh stop/deadline/auth/budget checks immediately before dispatch; durable atomic consumed reservation bound to this descriptor; one outstanding pair and no prior valid forecast; uncertain acknowledgement recovery without retry; private comment policy and any required public explanation separately approved. This candidate uses synthetic fixtures only and has not processed live competition questions. Registration/key handling/live forecasts remain unimplemented.
